# SuperSonic 语义元素识别方法论

> 适用范围：SuperSonic Headless BI 语义层 / Chat BI Schema Mapper
> 核心源码：`headless/chat/src/main/java/.../knowledge/`、`common/.../pojo/enums/DictWordType.java`
> 配套文档：[[自定义词典格式说明]]、[[自定义词典样例]]

本文档定义 SuperSonic 语义层中的五类核心元素 **DATASET / METRIC / DIMENSION / TERM / VALUE**，说明它们的代码定义、相互关系、样例，并给出一套从业务场景中识别这些元素的方法论，最终落地为 HanLP 自定义词典词条。

---

## 一、五类元素的定义

### 1.1 总览

| 元素 | `TypeEnums` | `SchemaElementType` | `DictWordType` 后缀 | nature 编码 | 词典词频 | WordBuilder |
|------|-------------|---------------------|---------------------|-------------|----------|-------------|
| **DATASET** 数据集 | `DATASET` | `DATASET` | (隐式,无后缀) | `_<dataSetId>` | 100000 | `DataSetWordBuilder` |
| **METRIC** 指标 | `METRIC` | `METRIC` | `metric` | `_<modelId>_<elementId>_metric` | 100000 | `MetricWordBuilder` |
| **DIMENSION** 维度 | `DIMENSION` | `DIMENSION` | `dimension` | `_<modelId>_<elementId>_dimension` | 100000 | `DimensionWordBuilder` |
| **VALUE** 维度值 | `VALUE` | `VALUE` | (隐式,无后缀) | `_<modelId>_<elementId>` | 聚合计算/可变 | `ValueWordBuilder` |
| **TERM** 业务术语 | (无对应) | `TERM` | `term` | `_<dataSetId>_<elementId>_term` | 100000 | `TermWordBuilder` |

> 还存在 `TAG`(标签)、`MODEL`(模型)、`DOMAIN`(域) 等类型，但进入词典参与分词识别的主要是上表五类（`TAG` 暂未注册 WordBuilder）。

### 1.2 DATASET 数据集

**定义**：对用户可见的、可被自然语言查询的"语义数据集合"的入口名称。它是 Chat BI 的**查询单元**——用户的一句话查询最终归属到某个 DataSet。一个 DataSet 聚合了若干 Model 的指标/维度/维度值，对外暴露统一口径。

**代码定义**：`SchemaElement.dataSetId / dataSetName`；`SchemaElementType.DATASET`。

**nature**：`_<dataSetId>`（仅一段数字，`DictWordType.getNatureType` 判定 `length==2 且第2段为数字` → DATASET）。

**作用**：分词命中后，`HanlpHelper.getTerms` → `NatureHelper.changeModel2DataSet` 把 modelId 翻译为 dataSetId，从而把查询路由到正确数据集。

**样例**：
```
销售分析 _1 100000          # dataSetId=1
流量看板 _2 100000          # dataSetId=2
```

### 1.3 METRIC 指标

**定义**：可被聚合计算的**度量**——业务关心的数值，通常带聚合函数（SUM/COUNT/AVG…）。回答"多少/多大幅度"的问题。

**代码定义**：`SchemaElement.type=METRIC`，含 `defaultAgg`（默认聚合）、`dataFormatType`（数据格式）。

**nature**：`_<modelId>_<elementId>_metric`。`modelId` 标识所属模型，`elementId` 是该指标在模型内的唯一 ID。

**字母词特殊处理**：含大写字母的指标名（`GMV`/`PV`/`UV`）在运行时由 `insert()` 以小写形式入 Trie，大写形式存入 `attribute.originals`，匹配后由 `transLetterOriginal()` 还原。**此类词条不写入词典文件**（会触发 `load()` 的 `Long.parseLong` 异常分支而中止加载）。

**样例**：
```
销售额 _1_101_metric 100000
访问时长 _1_105_metric 100000
# 多词性：同一词"访问"是两个模型的指标
访问 _1_106_metric 100000 _2_112_metric 100000
```

### 1.4 DIMENSION 维度

**定义**：用来**分组/筛选**指标的**分析视角**——业务观察数据的"角度"。回答"按什么看"的问题。维度本身是列名/字段名（如"城市"、"部门"），其取值集合才是 VALUE。

**代码定义**：`SchemaElement.type=DIMENSION`，可能含 `isPartitionTime`(时间分区)、`isPrimaryKey`(主键) 等属性。

**nature**：`_<modelId>_<elementId>_dimension`。

**样例**：
```
城市 _1_201_dimension 100000
部门 _1_1_dimension 100000
歌手 _2_7_dimension 100000
```

### 1.5 VALUE 维度值

**定义**：某个 DIMENSION 的**具体取值**——枚举值/维度成员。它是"维度"实例化后的具体值（"城市"维度下的"北京"、"上海"）。

**代码定义**：`SchemaElement.type=VALUE`，通过 `schemaValueMaps` 与所属维度关联。

**nature**：`_<modelId>_<elementId>`（**无类型后缀**，`elementId` 即所属维度的 id）。`getNatureType` 判定 `length==3 且第2、3段为数字` → VALUE。

**词频**：**不固定 100000**，而是按指标聚合计算得来（`Math.round(metric)`），白名单值另设 `itemValueWhiteFrequency`。词频反映该值在数据中的"重要性/频次"，用于 `NATURE_TO_VALUES` 高频队列排序。

**字母词**：大写维度值（`HR`/`App`）安全，因其 nature 末段为数字 → 走 `KnowledgeBaseService.addDimValueAlias(dimId,…)` 分支。

**空格占位**：含空格的值用 `#` 占位（`HanlpHelper.SPACE_SPILT="#"`），加载时 `getWordBySpace()` 还原。

**样例**：
```
北京 _1_201 8000          # 城市(维度201)的值，词频8000
HR _1_1 876               # 部门(维度1)的值
New#York _1_201 1200      # 含空格的值
App _1_204 9800
```

### 1.6 TERM 业务术语

**定义**：业务方自定义的**复合语义短语/同义词**——把一句口语化的表达映射到某个 DataSet 下的语义元素，用于弥补分词与同义词的语义鸿沟。它不是字段、不是指标，而是一种"业务黑话"到 Schema 的桥接。

**代码定义**：`SchemaElementType.TERM`；`NatureHelper.isTerm()` 判定 nature 以 `_term` 结尾。TERM 的 nature **不被** `changeModel2DataSet` 翻译（`isTerm` 直接原样返回），因为它本身已挂在 dataSet 下。

**nature**：`_<dataSetId>_<elementId>_term`（注意：用 `dataSetId` 而非 `modelId`，因为术语是 DataSet 级概念）。

**样例**：
```
环比增长 _1_301_term 100000
日活 _2_303_term 100000     # "日活" → dataSet 2 下的术语
```

## 二、元素间关系

### 2.1 结构关系图

```
                        ┌──────────────────┐
                        │     DATASET      │  对外查询单元
                        │  (dataSetId)     │
                        └────────┬─────────┘
                                 │ 聚合若干 Model
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
        ┌──────────┐       ┌──────────┐       ┌──────────┐
        │  MODEL   │  ...  │  MODEL   │       │  MODEL   │
        │(modelId) │       │(modelId) │       │(modelId) │
        └────┬─────┘       └────┬─────┘       └────┬─────┘
             │                  │                  │
    ┌────────┴────────┐  ┌──────┴──────┐    ┌──────┴──────┐
    │                 │  │            │    │            │
    ▼                 ▼  ▼            ▼    ▼            ▼
┌─────────┐    ┌─────────────┐  ┌─────────┐    ┌─────────────┐
│ METRIC  │    │ DIMENSION   │  │ METRIC  │    │ DIMENSION   │
│(聚合度量)│    │ (分析视角)   │  │         │    │             │
└─────────┘    └──────┬──────┘  └─────────┘    └─────────────┘
                      │ 取值集合
                      ▼
                ┌──────────┐
                │  VALUE   │  维度的枚举值
                │ (维度值)  │
                └──────────┘

   TERM 横跨挂在 DATASET 下，桥接口语表达 → Schema 元素
   (TERM 的 nature 用 dataSetId，不归属某个 Model)
```

### 2.2 关键关系要点

| 关系 | 说明 | 代码体现 |
|------|------|----------|
| **DATASET ⊃ MODEL** | 一个 DataSet 聚合多个 Model；查询时通过 `modelIdToDataSetIds` 映射把 Model 级 nature 翻译为 DataSet 级 | `NatureHelper.changeModel2DataSet(nature, modelIdToDataSetIds)` |
| **MODEL ∋ METRIC / DIMENSION** | 指标、维度归属某个 Model，nature 第一段即 modelId | `_<modelId>_<elementId>_(metric\|dimension)` |
| **DIMENSION ∋ VALUE** | 维度值隶属于某维度；VALUE 的 nature 复用所属**维度的 modelId + 维度自身 elementId**，故"维度 201 的值"nature 为 `_1_201` | `ValueWordBuilder.getOneWordNature` |
| **TERM ⊂ DATASET** | 术语挂在 DataSet 级，nature 用 dataSetId；不被 model→dataset 翻译，原样进入分词结果 | `TermWordBuilder` 用 `schemaElement.getDataSetId()`；`NatureHelper.isTerm` 短路 |
| **METRIC ↔ DIMENSION 正交** | 指标是"量"，维度是"轴"；查询 = 按若干 DIMENSION 分组聚合若干 METRIC | `DataSetInfoStat` 分别统计 `metricDataSetCount` / `dimensionDataSetCount` |
| **VALUE 依赖 DIMENSION** | VALUE 不能独立存在，必须有归属维度；维度值词频反映其在数据中的分布 | `SchemaElement.schemaValueMaps` |

### 2.3 ID 一致性约定（落地词典时的硬约束）

- **维度与其值共享 modelId + elementId**：`城市 _1_201_dimension` 的值必须用 `_1_201`。
  ```
  城市 _1_201_dimension 100000   # 维度本身
  北京 _1_201 8000              # 该维度的值（同 modelId=1, elementId=201）
  ```
- **指标 elementId 与维度 elementId 不冲突**：同一模型内指标、维度各自独立编号。
- **DATASET 的 id 与 MODEL 的 id 是不同命名空间**：`_<1>` 可能是 dataSet 也可能是 modelId，区分依据是 `getNatureType`（`length==2`→DATASET；`length>=3 且无后缀`→VALUE）。

## 三、识别方法论

面对一个业务场景，按以下五步把业务实体识别为五类元素并落地为词典词条。

### 第 1 步：划定 DATASET 边界（先定"问什么"）

**问**：用户会以"一句话"问到的、自洽的最小可查询单元是什么？

- 一个 DataSet = 一组逻辑相关的指标+维度，构成一个完整的分析主题。
- 粒度判据：能独立回答业务问题、且不需要跨主题 JOIN。
- **样例**：电商场景 → `销售分析`（含销售额、访问时长、城市/部门维度）；音乐场景 → `流量看板`（含播放量、歌手/流派维度）。

**产出**：`<主题名> _<dataSetId> 100000`。

### 第 2 步：拆 MODEL 与归属（再定"数据从哪来"）

**问**：DataSet 背后的物理/逻辑模型是什么？哪些指标/维度来自同一张表（同一 modelId）？

- 一个 Model 对应一张逻辑表/一个数据源。
- 同名指标跨 Model（如"访问"既是销售模型的也是流量模型的）→ 各自独立 elementId，nature 不同 → 自然支持多词性合并。
- **产出**：为每个 Model 分配 `modelId`，后续指标/维度的 nature 第一段都用它。

### 第 3 步：分指标 vs 维度（量与轴的二分）

对每个字段问一个判别问题：

> **"它是用来算/比较数值的（指标），还是用来分组/筛选的（维度）？"**

| 判据 | METRIC 指标 | DIMENSION 维度 |
|------|-------------|----------------|
| 可否聚合（SUM/AVG/COUNT） | ✅ 可以 | ❌ 不可以（聚合无意义） |
| 数据类型 | 数值 | 文本/类别/时间/ID |
| 回答的问题 | "多少/多大幅度" | "按什么看/筛哪些" |
| 例子 | 销售额、PV、访问时长 | 城市、部门、歌手、日期 |

**边界警示**：
- "日期/时间"通常归 DIMENSION（时间分区维度，`isPartitionTime`）。
- "金额"是 METRIC，但"金额区间"（0-100/100-500）是 VALUE 或独立分桶维度——视建模方式而定。
- 同名字段在不同模型里可能角色不同，按所属 Model 单独判定。

**产出**：
- 指标：`<指标名> _<modelId>_<metricElementId>_metric 100000`
- 维度：`<维度名> _<modelId>_<dimElementId>_dimension 100000`

### 第 4 步：枚举 VALUE（维度的取值）

**问**：每个 DIMENSION 的实际取值有哪些？哪些值得入词典？

- 仅对**枚举型/低基数**维度枚举值（城市、部门、歌手、流派）。
- 高基数维度（订单号、用户ID）不入词典，靠运行时匹配。
- **词频**：按该值在数据中的出现/聚合频次赋值，而非固定 100000；高频值优先（进入 `NATURE_TO_VALUES` 的 `MAX_SIZE=10` 队列）。
- **归属约束**：VALUE 的 nature 必须复用所属维度的 `modelId_elementId`。
- **空格/字母处理**：含空格用 `#` 占位；大写字母值（`HR`/`App`）安全可入文件。

**产出**：
```
北京 _1_201 8000          # 维度201(城市)的值
HR _1_1 876               # 维度1(部门)的值
New#York _1_201 1200
```

### 第 5 步：补 TERM（业务黑话桥接）

**问**：有没有口语/行业黑话无法靠分词或同义词覆盖的表达？

- TERM 用于"复合语义短语"，把 `环比增长`、`日活`、`DAU` 这类**非字段名**的口语映射到 DataSet 下的具体语义。
- 触发条件：①该短语需跨指标/维度组合才有意义；②字段别名无法覆盖；③用户高频使用。
- nature 用 **dataSetId**（不是 modelId），挂在 DataSet 级。

**产出**：
```
环比增长 _1_301_term 100000
日活 _2_303_term 100000
```

### 识别决策树（快速参考）

```
业务实体
  │
  ├─ 是"可查询的主题入口"？ ──── DATASET  (_<dataSetId>)
  │
  ├─ 是"口语黑话/复合短语"？ ──── TERM     (_<dataSetId>_<eid>_term)
  │
  └─ 是数据字段？
       │
       ├─ 可聚合的数值？ ───────────── METRIC   (_<modelId>_<eid>_metric)
       │
       └─ 分组/筛选的视角？
            │
            ├─ 字段名本身 ─────────────── DIMENSION (_<modelId>_<eid>_dimension)
            │
            └─ 字段的具体取值 ─────────── VALUE    (_<modelId>_<dimEid>)
```

## 四、落地为词典的硬约束（避坑）

识别完成后写入 `CustomDictionary.txt` 时，必须遵守 `MultiCustomDictionary.load()` 的解析约束，否则整个文件加载中止（`return false`/`return true`）：

| 约束 | 原因 | 对策 |
|------|------|------|
| **禁用 `#` 注释行** | `load` 按 `\s` 切分并对第 3 列起 `Integer.parseInt`，`# 注释…` 抛 `NumberFormatException` → `return false` 中止全文件 | 用空行分段（空行被跳过） |
| **字母词不得带非数字后缀 nature** | `isLetters(word)` 为真且大小写不同时，对 nature 末段 `Long.parseLong`；`_metric`/`_dimension`/`_term` 末段非数字 → `return true` 中止后续 | 指标/维度/术语名用**中文**；字母指标(GMV/PV)由运行时 `insert()` 注入，不入文件 |
| **字母词仅限 VALUE 型** | VALUE nature `_<modelId>_<dimId>` 末段为数字 → `addDimValueAlias` 成功 | 大写维度值(`HR`/`App`)可安全入文件 |
| **`#` 是空格占位符** | `SPACE_SPILT="#"`，`getWordBySpace()` 还原 | 含空格的词写作 `New#York` |
| **ID 一致性** | 维度与其值共享 `modelId_elementId` | 见 §2.3 |
| **多词性合并** | 同一 word 多行/nature 会被 `DictionaryAttributeUtil` 合并 | 跨模型同名指标可写一行：`访问 _1_106_metric 100000 _2_112_metric 100000` |

## 五、完整样例（电商+音乐双 DataSet）

以下样例与 `src/test/resources/data/dictionary/custom/CustomDictionary.txt` 一致，已通过 `CustomDictionaryFileTest` 验证可被 `MultiCustomDictionary.load()` 完整加载（54 词）。

```
销售分析 _1 100000
流量看板 _2 100000

销售额 _1_101_metric 100000
访问时长 _1_105_metric 100000
播放量 _2_111_metric 100000

部门 _1_1_dimension 100000
城市 _1_201_dimension 100000
渠道 _1_204_dimension 100000
歌手 _2_7_dimension 100000
地区 _2_4_dimension 100000

环比增长 _1_301_term 100000
日活 _2_303_term 100000

访问 _1_106_metric 100000 _2_112_metric 100000

HR _1_1 876
sales _1_1 872
北京 _1_201 8000
New#York _1_201 1200
App _1_204 9800
周杰伦 _2_7 100
Taylor#Swift _2_7 100
内地 _2_4 100
```

渲染为分组树（`CustomDictionaryFileTest.buildTextTree…` 的实际输出）：

```
└── CustomDictionary (54 words, 55 word-nature pairs)
    ├── DATASET (2 natures, 2 words)
    │   ├── _1 └── 销售分析 (freq=100000)
    │   └── _2 └── 流量看板 (freq=100000)
    ├── METRIC (5 natures, 5 words)
    │   ├── _1_101_metric └── 销售额 (freq=100000)
    │   ├── _1_106_metric └── 访问 (freq=100000)
    │   └── _2_112_metric └── 访问 (freq=100000)   # 多词性:同一词两个模型
    ├── DIMENSION (8 natures, 8 words) …
    ├── TERM (3 natures, 3 words) …
    └── VALUE (9 natures, 37 words)
        ├── _1_1 ├── HR (freq=876) ├── sales (freq=872) …
        └── _1_201 ├── 北京 (freq=8000) ├── New York (freq=1200) …
```

> **55 pairs = 54 words + 1**：`访问` 这一个多词性词条在 METRIC 分支出现两次，证明多词性解析与合并正确。

## 六、验证方式

落地后用 `CustomDictionaryFileTest` 验证：

1. `load_shouldParseEntireFileWithoutAborting` — `load()` 返回 true 且词数完整（未中途 abort）。
2. `load_shouldContainEntriesFromEveryCategory` — 每类元素都有代表词条且 nature 编码正确。
3. `load_shouldParseMultiNatureEntry` — 多词性词条携带多个 nature、`totalFrequency` 求和。
4. `load_shouldAcceptUppercaseValueWordsAndRestoreSpacePlaceholder` — 大写值词与 `#` 占位符还原。
5. `buildTextTree_shouldRenderDictionaryGroupedByCategoryAndNature` — 渲染分组树供人工复核。

运行：
```bash
mvn -pl headless/chat -am test \
  -Dtest=CustomDictionaryFileTest \
  -Dsurefire.failIfNoSpecifiedTests=false
```
